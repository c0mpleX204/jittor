Experiment goal
===============

Do not continue the old single-VM CDRefine route as the main path.

Instead, add distribution constraints directly inside the multi-VM / CVM
training target. The goal is:

1. keep the CVM's surface/P2S strength,
2. improve CD by preserving clean patch coverage and local density,
3. avoid a two-stage pipeline where stage 1 damages distribution and stage 2
   tries to repair it from only local patch information.

Suggested new model
===================

Create a new model class instead of modifying the existing CVM destructively:

StraightPCFCoupledVelocityDistributionModule

Suggested new file:

src/model/straightpcf_cvm_distribution.py

Register it in:

src/model/parse.py

Implementation idea
===================

Keep the original CVM losses:

- direction loss
- consistency loss

Then add small-weight distribution constraints on the predicted output patch:

loss = cvm_loss
     + chamfer_weight * chamfer(pc_pred, pc_clean)
     + surface_weight * surface_proxy(pc_pred, pc_clean)
     + residual_weight * ||pc_pred - pc_current||^2
     + density_weight * density_matching(pc_pred, pc_clean)

Definitions:

pc_current:
  The current interpolated patch from cache, usually batch["pc_mix"].

pc_clean:
  The target surface/clean patch from cache, batch["pc_clean"].

pc_pred:
  The output patch after applying the coupled VMs from pc_current.

cvm_loss:
  Original StraightPCFCoupledVelocityModule loss. Do not delete it.

chamfer(pc_pred, pc_clean):
  Directly encourages the output patch to cover the clean patch, helping CD.

surface_proxy(pc_pred, pc_clean):
  Uses pc_clean as a surface proxy for now, keeping output near the surface.
  Later this can be replaced with exact mesh closest-point supervision.

residual_anchor:
  Penalizes excessive movement, for example ||pc_pred - pc_current||^2. This
  prevents the model from moving points too aggressively to satisfy Chamfer.

density_matching:
  Do not use a blind "push all points apart" loss at first. Prefer matching the
  local kNN distance distribution of pc_pred to pc_clean. This is safer for
  edges and thin structures.

Important implementation detail
===============================

Do not compute Chamfer and density on all 1000 patch points at first. Randomly
sample a subset to save memory and time.

Suggested settings:

num_dist_points: 256
density_k: 8 or 16

Start with the minimal stable version:

1. original CVM loss
2. small Chamfer loss
3. small residual anchor

Only add density matching after the minimal version is confirmed useful.

Evaluation criteria
===================

Always report:

Mean CD score
Mean P2S score
Mean final score

Current full-test baseline:

CD 58.6531
P2S 78.6321
final 68.6426

Decision rules:

CD +1 and P2S drop < 1:
  Continue.

CD +2 and P2S drop 1-2:
  Still worth continuing.

P2S drop > 3 and final does not improve:
  Loss is too aggressive. Lower chamfer/density/surface weights or LR.

CD and P2S both improve:
  Continue 10 more epochs.

How to shorten testing time
===========================

Full local test is about 100 samples. Prediction is slow because every sample
does FPS, KNN patch extraction, CVM denoising, and patch stitching.

For checkpoint screening, create a fixed half test list:

cd /root/src/starter_code

python - <<'PY'
from pathlib import Path
src = Path("datalist/noisy_test.txt")
lines = [x.strip() for x in src.read_text().splitlines() if x.strip()]
quick = lines[::2]
Path("datalist/noisy_test_half.txt").write_text("\n".join(quick) + "\n")
print(len(quick), "/", len(lines))
PY

cat > configs/data/predict_noisy_test_half_tmp.yaml <<'YAML'
predict_dataset:
  shuffle: False
  batch_size: 1
  num_workers: 0
  datapath:
    input_dataset_dir: /root/autodl-tmp/noisy_test
    use_prob: False
    loader: npy
    data_name: noisy.npy
    ignore_check: True
    data_path:
      shapenet: [
        [./datalist/noisy_test_half.txt, 1.0],
      ]
YAML

Important:

half score can only be compared with a half baseline.
Do not compare half score directly with the full100 score 68.6426.
Final candidates must be scored on full100.

Training efficiency
===================

Use patch cache:

12000 cache
batch_size = 2
num_workers = 0

Expected log:

6000 batches/epoch
about 2m20s/epoch

Do not blindly use num_workers=2. It was unstable before. With patch cache,
num_workers=0 is already fast.

If GPU memory is very free, cautiously try:

batch_size = 4

Run 1 epoch first to check OOM and loss.

Denoise / scoring efficiency
============================

Use half set for checkpoint screening.
Run full100 only for final candidates.

Use:

--workers 8

for scoring. If CPU is idle, try:

--workers 16

The truly lossless future optimization is predict patch cache: cache noisy_test
FPS/KNN patch indices and stitching information. It is not implemented yet.

Do not do
=========

Do not:

1. Go back to single-VM CDRefine as the main route.
2. Train the distribution model from scratch.
3. Commit temporary YAML files before results are confirmed.
4. Judge by loss only; always score CD/P2S.
5. Compare half-set score directly to full100 score.
6. Start with a large density loss.

Recommended first implementation
================================

Start with:

original CVM loss
+ chamfer(pc_pred, pc_clean)
+ residual_anchor

Do not add density first. If this improves CD without breaking P2S, then add
density matching later.
